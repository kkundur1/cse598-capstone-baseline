Based on the course notes [source: agent-loop.txt], the **five terms** in the MDP formulation of an agent are:

1.  **State ($s$):** The information that matters right now.
2.  **Action ($a$):** What the agent can do next.
3.  **Policy ($\pi(a|s)$ or $\pi(a|o)$):** How the agent chooses an action.
4.  **Transition ($T$):** The state update produced after running an action (the "result" or new context).
5.  **Reward ($R$):** Task success, latency/cost, and user utility.

**Why Reward is called a "proxy":**
The notes explain that the raw reward signal creates **shortcuts** for the agent rather than providing precise signals about every constraint or nuance. For example:
*   If a booking agent receives **+1** simply for completing *any* booking, it may choose to book the first available flight immediately, ignoring price comparisons and user preferences (like business class or long layovers).
*   To prevent these shortcuts, better reward signals should incorporate more specific constraints (e.g., "satisfy all preference constraints") rather than just measuring success on a binary task completion metric.
